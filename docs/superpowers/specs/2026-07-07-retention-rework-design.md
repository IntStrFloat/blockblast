# Retention-rework: дейли-цикл за игру, кривая прогрессии, косметика-витрина, уведомления

Дата: 2026-07-07. Статус: одобрено пользователем (включая решения: дейли-цель 10→5 уровней, лимит 1 пуш/день, двухступенчатый бонус, полный объём косметики клиент+бэкенд, expo-notifications).

## Зачем

Метрики за июнь–июль 2026: D1 24%, D7 8%, D14 2%; возвраты 0–3/день; DAU держится притоком.
Диагноз: retention-мета (Капи, уровни, дейли-клейм) либо математически недостижима
(уровень = 14 000 очков ≈ 14 медианных партий), либо не создаёт сессию (клейм за открытие).
Работающие якоря — Adventure и недельный турнир. Rework переподчиняет слабые фичи сильным.

## 1. Дневной цикл: бонус за игру

### Механика (features/dailybonus)

Двухступенчатый дейли-бонус вместо кнопки «забрать» на Home:

- **Ступень 1 «первая победа дня»** — первая за день:
  - классика: завершённая партия с ≥1 очищенной линией (game over или выход с сохранением НЕ считается — только завершение партии; критерий линии проверяется по итогам партии), либо
  - Adventure: победа на уровне.

  Начисляет `basePoints × streakMultiplier[визуальный стрик]` в Уровень Игры (как сейчас `claim()`).
  Показывается celebration-моментом на экране результата (см. Презентация).
- **Ступень 2 «цель дня»** — `ADVENTURE_CONFIG.dailyGoalLevels` побед в Adventure за день
  (**снижаем 10 → 5**). Даёт **гарантированный дроп**: helperCharge/cosmetic по `dropRarity`;
  на живом стрике, кратном 7, — гарантированная косметика (`day7GuaranteedCosmetic`).
  Случайный `dropChanceByStreak` удаляется: дроп теперь только за цель дня.

Store `useDailyBonus`: `lastClaimDay` (ступень 1) + новое поле `lastGoalClaimDay` (ступень 2),
методы `claimFirstWin()` и `claimDailyGoal()` — идемпотентны в пределах дня. Публичный
`canClaim()`-путь и кнопка клейма удаляются. Вызовы:

- `claimFirstWin` — из game store в момент фиксации game over (классика, linesCleared ≥ 1)
  и из adventure store `recordWin`.
- `claimDailyGoal` — из `recordWin`, когда `daily.cleared` достигает цели.

Стрик не меняется: `markPlayedToday()` в game store уже бампает за партию; множитель растёт игрой.

### Миграция

`lastClaimDay` сохраняется как есть: кто уже забрал бонус сегодня по-старому — ступень 1
сегодня не начисляется повторно. `lastGoalClaimDay` стартует `null`.

### Презентация

- **Экран результата** (game over классики / LevelResultView Adventure): при срабатывании
  ступени блок «Дейли-бонус +N ×M 🔥 день K» с лёгкой анимацией появления (Reanimated,
  вне drag-пути); для ступени 2 — «Цель дня выполнена! 🎁 <дроп>». Тон и типографика —
  по спеке 04 (AppText-пресеты, цвета из ui/theme).
- **DailyCard на Home** → статус дня (без кнопки):
  лесенка стрика (как сейчас) + строки ступеней:
  «Сыграй партию → +N ×M» / «✓ Забрано +N», «Цель дня 3/5 → 🎁» / «✓ 🎁 получен».
  Тап по карточке ведёт в Adventure, если цель не выполнена.
- **AdventureEntryCard**: строка «Сегодня: 3/5» с мини-прогрессбаром и иконкой подарка
  на конце; выполненная цель — заполненный бар + галочка.
- i18n ru/en для всех строк.

### Аналитика

`daily_bonus_stage: { stage: 'firstWin' | 'goal'; points?: number; multiplier?: number; dropType?: string }`
заменяет `daily_bonus_claimed`; `adventure_daily_goal_done: { cleared: number }`.

## 2. Кривая прогрессии (features/progression)

`PROGRESSION_CONFIG`:

- `levelCost: { base: 2500, growth: 1.12 }` (было 14000 / 1.16);
- `tierGaps: [3, 4, 5, 6, 7, 8, 9]` (было [5,7,9,11,14,18,22]);
- `levelRewards` переякорить плотнее в начало: уровни 1–5 — по награде каждый
  (1 косметика, 2 helper hint, 3 косметика, 4 косметика, 5 helper swap), дальше
  существующие предметы реже; состав предметов не меняется, только уровни.

Ожидаемый темп (медианная партия ≈ 1000 очков, ~3 партии/день + дейли-бонус):
уровень 1 — первая сессия; мир 2 — ~2–3 дня; дальше интервал растёт.

Миграция: `lifetimePoints` не трогаем; уровень/мир — производные от кривой, при первом
запуске после апдейта пересчитываются и все награды уровней ≤ нового уровня выдаются
(идемпотентно — по уже существующему механизму выдачи наград level-up; проверить, что
догоняющая выдача не показывает N оверлеев подряд — максимум один суммарный момент).

Новые события: `level_up: { level: number; world: number }`,
`world_unlocked: { world: number }`, `streak_lost: { count: number }` (при сбросе стрика).

Новый контент в ветку прогрессии не добавляется (решение из обсуждения).

## 3. Косметика — витрина достижений

### Витринный образ (showcase)

Экипированный образ Капи (skin + hat + face + acc) сериализуется в компактную строку
`avatarId` (формат `skin|hat|face|acc` из id каталога cosmetics, пустые слоты — пусто).
Рендер — маленький аватар-бейдж (готовый компонент на базе существующего рендера Капи):

- в ProfileOverlay рядом с ником;
- в каждой строке лидерборда (LeaderboardRow) рядом с ником; чемпионская рамка
  (`championRankOf`) сохраняется и совмещается с бейджем.

### Протокол и бэкенд (backend/server.cjs)

- submit рекорда: поле `avatar?: string` (валидация: длина ≤ 64, паттерн из id-чарсета,
  неизвестные id слотов — отбрасывать слот, невалидное поле целиком — игнорировать, не 4xx);
- список лидерборда: `avatar` в каждой записи;
- хранение — в записи игрока (последний присланный);
- тесты в backend/__tests__/server.test.cjs; деплой сервера — отдельный шаг после мержа
  (Node18/systemd, см. memory leaderboard-backend).
- Клиент обязан работать со старым сервером (avatar отсутствует в ответе → без бейджа).

### Сезонные награды Adventure

Конфиг `SEASON_REWARDS: Record<seasonId, cosmeticId>` (эксклюзивные предметы, не входящие
ни в dailyCosmeticPool, ни в levelRewards, ни в WEEKLY_PRIZES). Выдача — в `recordWin`
при завершении сезона, показ — в существующей сезонной церемонии (`lastWinCompletedSeason`).
Событие `season_reward_granted: { seasonId: number; cosmeticId: string }`.

### Фикс пересечения пулов

Из `DAILY_CONFIG.dailyCosmeticPool` убрать `hat-block-crown`, `face-monocle`, `acc-cape`
(эксклюзив призов турнира). Пул пополнить предметами каталога, не занятыми наградами;
при нехватке — добавить 2–3 новых предмета в каталог косметики.

### «Тебя обогнали»

При обновлении снапшота лидерборда: если ранг игрока упал относительно прошлого снапшота
той же недели — заметный баннер на WeeklyCard и экране лидерборда
(«Тебя обогнал <ник> — отыграйся!»), событие `overtaken_shown: { from: number; to: number }`.
Показывается однократно на факт падения (гасится при просмотре).

## 4. Локальные уведомления (features/notifications)

Новая зависимость **expo-notifications** (локальное планирование; пуш-приём остаётся
на RuStore). Обоснование добавить в спеку 07 (бюджет нативных зависимостей), механику —
в спеку 16.

### Планировщик

Чистая функция `planLocalNotifications(state, now): PlannedNotification[]`:
вход — стрик, lastClaimDay, снапшот лидерборда (ранг, играл ли на неделе), окно сезона
и прогресс Adventure; выход — список «когда + что». Правила:

1. 🔥 стрик: если стрик жив и сегодня не сыграно к вечеру — «Стрик N сгорит — забери +M
   за партию» на 19:00 локального дня, когда стрик умирает;
2. 🏆 воскресенье 18:00: «Турнир заканчивается, ты №N» — если играл на этой неделе;
3. 🎁 понедельник 11:00: «Итоги турнира готовы» — если играл на прошлой неделе;
4. ⏳ сезон Adventure: за 2 дня до конца окна, если сезон начат и не завершён.

**Лимит: максимум 1 уведомление в календарный день** — при конфликте выбирается верхний
по списку приоритет. Применение: при уходе приложения в фон (AppState) отменить все
запланированные и применить свежий план. Тап по уведомлению — роутинг на Home
(существующий routing.ts расширяется типом `local`).

### Разрешение

Soft-ask по существующему паттерну (PushSoftAskSheet), показывается один раз в позитивный
момент — сразу после первого полученного дейли-бонуса (ступень 1). Отказ — не переспрашиваем
(как в текущем softAsk). Android 13+ — системный запрос POST_NOTIFICATIONS через
expo-notifications; до 13 — разрешение не требуется.

События: `notification_scheduled: { kind: string }`, `notification_opened: { kind: string }`.
