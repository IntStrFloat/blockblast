# 09 — Маскот «Капи» (retention-компаньон)

Статус: черновик на ревью · Обновлено: 2026-06-13

Зверёк-компаньон, который живёт в верхней части игрового экрана, бродит по «полу» (верхней кромке доски), реагирует на игру и **прокачивается от активности игрока**. Цель — рост retention (D1/D7/D30) через эмоциональную привязанность и ежедневный крючок возврата, **без нарушения чистого core loop и анти-чеклиста (спека 06)**.

Связанные спеки: [01-screens](01-screens.md), [02-architecture](02-architecture.md), [03-game-engine](03-game-engine.md), [04-design-system](04-design-system.md), [05-monetization](05-monetization.md), [06-audience](06-audience.md), [07-performance](07-performance.md). Точечные правки этих спек — в §20.

---

## 1. Назначение и цель

- **Зачем.** В чистом аркадном Block Blast нет причины возвращаться завтра, кроме желания побить рекорд. Маскот добавляет вторую петлю удержания: «мой питомец растёт, пока я играю; зайду — покормлю, увижу, как он эволюционировал».
- **Метрика успеха.** Рост retention и средней длины серии дней (стрик), без падения core-метрик (ср. длина сессии, fps, % дропа из-за навязчивости — должен остаться нулевым).
- **Жёсткие рамки.** Только косметика как основа прогрессии; «мягкие помощники» зарабатываются игрой, не деньгами (не P2W); ноль блокирующих попапов; работает оффлайн; держит бюджет 60fps (спека 07).

## 2. Обоснование (анализ ЦА СНГ Gen Z / Alpha)

Полный ресёрч — в истории проекта; ключевые выводы и 5 рычагов, на которых построен «Капи»:

| Рычаг | Откуда | Как реализован в «Капи» |
|---|---|---|
| **Чилл-якорь** | Капибара — главный мем-зверь Рунета 2023–24 (символ невозмутимого дзена), идеален под расслабляющую головоломку | «Капи» — стилизованный капибара-вайб: сонно-довольный, неторопливый |
| **Ugly-cute > приторного** | Labubu/Pop Mart-краза 2025 в РФ (+600% акций): «страшно-милое» запоминается | Чуть «игрушечный винил», не сахарный; запоминающийся силуэт с блоком на макушке |
| **Коллекционность + сюрприз** | Blind-box дофамин (Labubu) | Левел-ап = сюрприз-распаковка косметики (бесплатно, за игру) |
| **Абсурдный лор + дикое разнообразие поведения** | Итал. брейнрот; принцип 06 «абсурдизм > прямых мемов» | ~28 микро-действий + контекстные триггеры → не видно скриптованности |
| **Реактивность / «общается со мной»** | Тамагочи/Finch-эффект + уют стримерских чатов | Реагирует на каждое игровое событие эмоциями; ежедневное «кормление» |

Тон попадания: рунет-ирония, mass-safe по умолчанию; жёсткий сленг — только под тумблером «Дерзкий» (см. §3.4 и правку 06 в §20).

## 3. Персонаж «Капи»

### 3.1. Идентичность
- **Имя:** Капи (внутр. id `capi`). Вид — чилловый зверёк капибара-энергии.
- **Характер:** невозмутимый, ленивый-добрый, чуть ироничный. Никогда не агрессивный, не «вымогает» внимание.
- **Подпись:** глянцевый **блок на макушке** (из мира игры) — главный узнаваемый признак; появляется со 2-й стадии.

### 3.2. Внешний вид (база)
- **Цвет/материал:** «лавандовый винил» — мягкий сине-сиреневый глянцевый корпус, читается на тёмно-синем фоне игры, попадает в коллекционный вайб.
  - Палитра (черновые токены, финал — в `ui/theme.ts`, см. §20): корпус-градиент `#B3B9F2 → #7C84E6`, уши `#666FD8`, мордочка `#CDD2F9`, румянец `#F2A6D8`, обводка глаз/рта `#2B2440`, блок-подпись `#FFD23F`.
- **Силуэт:** «лоф» — горизонтально-вытянутое скруглённое тело, маленькие круглые уши, тупая мордочка, сонно-довольные глаза (дуги), стубби-лапки. Лёгкий глянцевый блик сверху.
- **Размер на экране:** ~52–64px по высоте (≈ высота одной фигуры трея), масштабируется от высоты доступной полосы.

### 3.3. Стадии эволюции (производны от уровня, см. §7)

| Стадия | Уровни | Вид |
|---|---|---|
| 1 · «Малыш Капи» | 1–4 | Кругленький, глазастый, **без** блока на макушке (ещё не заслужил), большие открытые глаза |
| 2 · «Капи» | 5–11 | Базовая форма: блок-подпись на макушке, сонно-довольные глаза |
| 3 · «Чилл-Капи» | 12–19 | Чуть крупнее, «лук» из разлоченных аксессуаров (очки, наушники и т.д.) |
| 4 · «Капи-Легенда» | 20–24 | Корона из блоков, аура-свечение, искры — статус «давно в игре» |

Стадия меняет базовый рендер; косметика (§8) накладывается поверх независимо.

### 3.4. Голос и тон (важно)
- **По умолчанию «Капи» МОЛЧИТ** — выражает себя только действиями и эмоциями (визуальные эмоты без текста: `✨ 💤 ❗ ♥ 💢 💧 ♪ 💭`).
- **Текстом говорит ровно в двух случаях:** (1) когда его уронили/выкинули — фраза потери (§10.4); (2) разовое интро при первом заходе (§11).
- Эти тексты подчиняются тумблеру тона: **ирония включена всегда** (mass-safe формулировки), **жёсткий Gen-Z-сленг — только при «Дерзкий»**. Это задокументированное исключение к принципу 06 №4 (см. §20).

## 4. Размещение и рендеринг

### 4.1. Размещение
- «Капи» живёт в **верхней части экрана**, в зазоре между HUD и доской. Его **«пол» — верхняя кромка доски** (тонкая световая линия). Он бродит по ней влево/вправо в пределах ширины доски.
- **Не занимает игровую зону:** доска (фикс. квадрат `width − 32`, спека 04) и трей не уменьшаются. На коротких экранах полоса тоньше → «Капи» чуть ниже ростом, но не залезает на доску.
- UI прокачки (чип уровня + XP-бар) — компактный, в левом верхнем углу полосы; реплики-пузыри (только §10.4/§11) — над «Капи».

### 4.2. Рендеринг (ноль новых нативных зависимостей)
- «Капи» — **композиция Animated-View** (тело, уши, глаза, мордочка, блок, аксессуары) + `expo-linear-gradient` (уже в зависимостях) для глянца + **Reanimated 4** shared values для всей анимации. Согласуется с решением 07 «Views + Reanimated, не Skia». **react-native-svg не добавляем.**
- Органические детали (дуги глаз/рта) — скруглённые/повёрнутые View либо один лёгкий статичный PNG-ассет на деталь через `expo-image` (тоже без новой нативной зависимости). Предпочтение — View-композиция.
- Анимации движения: ходьба = `translateX` контейнера + лёгкий bob (`translateY` синусом) + покачивание ушей/лап; squash-stretch = `scaleX/scaleY`; моргание = `scaleY` глаз; всё — только transform/opacity (composited).
- Тень под ногами — отдельный View (овал, opacity).

## 5. Поведенческий движок (анти-скриптованность)

Ядро core-запроса: «много действий, чтобы не было видно скриптованности».

### 5.1. Принцип
- Не хардкод-последовательность, а **weighted-scheduler**: когда текущее действие завершилось, следующее выбирается случайно из доступных с учётом весов, кулдаунов, стадии, времени суток и настроения.
- **Контекстные триггеры важнее рандома:** игровое событие (§6) прерывает idle-петлю реакцией.
- **Детерминизм для тестов:** планировщик — чистая функция на `mulberry32` (`core/engine/rng`), seed хранится в сторе → поведение воспроизводимо в unit-тестах.

### 5.2. Контракт (чистый TS, `features/mascot/logic/behavior.ts`)
```ts
type ActionId = 'walkLeft' | 'walkRight' | 'idle' | 'sit' | 'lieDown' | 'sleep'
  | 'yawn' | 'stretch' | 'scratch' | 'lookScore' | 'lookBoard' | 'lookPlayer'
  | 'wave' | 'balanceBlock' | 'rollBlock' | 'pushBlock' | 'peekDown' | 'sniff'
  | 'groom' | 'dance' | 'spin' | 'hop' | 'ponder' | 'sparkleIdle' | 'sneeze'
  | 'wobble' | 'faceplant' | 'blink' /* частый авто-оверлей */ | /* …полный набор в config */;

interface BehaviorAction { id: ActionId; durationMs: number; dir?: -1 | 1; emote?: EmoteId; }
interface BehaviorCtx { stage: 1|2|3|4; hourOfDay: number; reduceMotion: boolean; }

/** Выбор следующего idle-действия. Детерминирован по rngState. */
function nextAction(
  recent: ReadonlyMap<ActionId, number>, // ts последнего запуска (для кулдаунов)
  now: number,
  ctx: BehaviorCtx,
  rngState: number,
): { action: BehaviorAction; rngState: number };
```

### 5.3. Каталог действий (черновик, веса/кулдауны — в `MASCOT_CONFIG`)
~28 действий. Представительная выборка:

| Действие | Вес | Кулдаун | Стадия | Прим. |
|---|---|---|---|---|
| walkLeft / walkRight | высокий | — | все | базовая ходьба, dir случаен, в пределах пола |
| idle / sit / lieDown | средний | — | все | паузы |
| blink | авто | 2–6с | все | постоянное лёгкое моргание (поверх любой позы) |
| yawn / stretch / scratch / groom | низкий | 20–40с | все | «живость» |
| sleep (💤) | растёт ночью | — | все | после 22:00 и при долгом простое |
| balanceBlock / rollBlock / pushBlock | низкий | 30с | 2+ | игра с блоком-подписью |
| lookScore / lookBoard / peekDown | средний | 8с | все | «следит» за партией |
| wave / lookPlayer (♥) | низкий | 25с | все | редкий зефир в сторону игрока |
| dance / spin / hop | низкий | 15с | все | чаще как реакция (§6) |
| ponder (💭) / sniff / sneeze / wobble / faceplant | очень низкий | 40–90с | 2+ | редкие «изюминки», чтобы ловить «о, он умеет и так» |

### 5.4. Модуляторы
- **Время суток:** после 22:00 веса sleep/yawn/lieDown растут (рифма с «ночным режимом» из 06, v1.1).
- **Настроение (производное, не персистим):** `happy` (после очистки/кормления), `neutral`, `sad` (долго не кормили / недавно потерялся) — слегка меняет веса и эмоты.
- **Кулдауны** не дают повторов → почти не видно скриптованности.
- **reduce-motion:** реже и медленнее, без резких spin/hop/faceplant.
- **Частота реплик:** реплик в обычной игре нет вообще (только эмоты), §3.4.

## 6. Реактивность (игровые события → реакции)

«Капи» подписан на `useGameStore` (`lastEvent: PlacementEvent`, `finalResult`, события старта/конца партии и drag). Реакция прерывает idle-петлю:

| Событие | Источник | Реакция (только эмоция, без текста) |
|---|---|---|
| Валидный дроп | `PlacementEvent.placed` | короткий кивок |
| Очистка ≥1 линии | `clearedRows/Cols` | хлопает/радуется, `✨` |
| Комбо ≥3 | `event.onFire` | танцует, `🔥`-эмот (визуальный, не текст) |
| Новый рекорд | `finalResult.isRecord` | прыжок + искры, синхронно с конфетти GameOver |
| Почти game over (мало ходов) | эвристика `findPlacements` < N | нервно подглядывает, `💧` |
| Game over | `event.gameOver` | оседает, `💤` |
| Тап по «Капи» | gesture (§10.1) | сердечко/подпрыгнул/потянулся |
| Кормление | §10.2 | ест блок, довольная анимация |
| Левел-ап | прогрессия (§7) | сюрприз-распаковка (§7.4) |
| Уронили | gesture (§10.4) | падает + единственная текст-реплика |

Реакции — **на UI-потоке**; XP начисляется в JS на `lastEvent` (вне горячего drag-пути).

## 7. Прокачка (XP и уровни)

### 7.1. Источники XP (гибрид)
- **Игровые действия (в моменте):** за очищенную линию, бонус за комбо-тир, бонус за новый рекорд, бонус за board-clear. Капает во время партии → дофамин «расту, пока играю».
- **Ежедневный бонус («кормление»):** крупный единоразовый XP раз в день (§10.2), завязан на день/стрик. Главный крючок возврата.

Черновые числа (финал — в `MASCOT_CONFIG`, как `GameConfig`):
```ts
xpPerClearedLine: 3,
xpComboTierBonus: 1,      // × текущий combo
xpNewRecord: 50,
xpBoardClear: 20,
dailyFeedXp: 40,
```

### 7.2. Кривая (24 уровня, длинный хвост)
- `xpToNext(level)` — растущая функция (черновик: `round(40 * 1.18^(level-1))`), полный массив порогов — в конфиге, балансируется без кода.
- Уровень — производное от `totalXp`; в сторе кэшируем `level` и `xpInLevel` для UI.
- На MAX (24) XP-бар замирает на «легенде»; кормление/игра продолжают давать эмоции, но не уровни (можно ввести «престиж»-метку в v1.1).

### 7.3. Награды по уровням
- **Каждый** уровень (кроме стадий-переходов, которые меняют форму сами) даёт **один косметический предмет** через сюрприз-распаковку (§8).
- **Вехи дают мягкого помощника** (§9): подсказка хода — **ур. 5**; унос непомещаемой фигуры — **ур. 12** (черновик).
- Таблица `LEVEL_REWARDS[level] = Reward` (косметика | помощник | смена стадии) — в конфиге.

### 7.4. Сюрприз-распаковка (blind-box дофамин)
- При левел-апе — короткий неблокирующий оверлей: коробка `🎁` подпрыгивает → «вскрывается» → вылетает предмет + название + «Капи» примеряет. Конфетти/искры (переиспользуем пул из `effects/`).
- **Идеальный UI:** появляется после завершения хода (не в drag), легко скипается тапом, не перекрывает критичные элементы, ≤1.2с, не копится в очередь (если левелов несколько — показываем дайджест «+N предметов»).

## 8. Косметика

- **Слоты:** `hat` (макушка/корона), `face` (очки/эмоции), `accessory` (наушники/шарф), `skin` (цвет корпуса, в т.ч. под темы поля), `aura` (стадия 4).
- **Каталог:** `features/mascot/logic/cosmetics.ts` — массив `{ id, slot, minStage, render }`. Добавление предмета не трогает компоненты (по аналогии с темами блоков 04).
- **Разлок:** через `unlocked: string[]`. **Надевание:** `equipped: Partial<Record<Slot, id>>`. Игрок может менять «лук» в мини-экране «Капи» (см. §10.5).
- v1: предметы только разлок-за-уровень. Платные паки — v1.1 (§18).

## 9. Мягкие помощники (UI должен быть идеальным)

Зарабатываются игрой (разлок по уровню), **лимит — раз в день каждый**, всегда опциональны, поданы как «Капи помогает». **Не P2W** (не продаются за деньги). Реализация обязана быть безупречной по UX — ниже требования.

### 9.1. Помощник A — «Подсказка хода» (разлок ур. 5)
- **Когда:** только когда игрок реально застрял — эвристика на `findPlacements`/`hasPlacement` (мало валидных позиций у текущего трея) ИЛИ ручной тап по «Капи» в таком состоянии.
- **Действие:** «Капи» доходит до края, показывает лапкой на **реально валидную** позицию (`findPlacements(board, shape)` даёт `(trayIndex, r, c)`), подсвечивает ghost-блоками (переиспользуем превью-подсветку из drag-системы).
- **Идеальный UI:** мягкий, **не мигающий** CTA, появляется **только** при реальном «стаке»; ноль ложных срабатываний; чёткий, но ненавязчивый; после использования — индикатор кулдауна («снова завтра»); никогда не делает ход за игрока (только показывает).

### 9.2. Помощник B — «Унести фигуру» (разлок ур. 12)
- **Когда:** в трее есть **гарантированно непомещаемая** фигура (`!hasPlacement(board, shape)`), а другие — мешает только она.
- **Действие:** «Капи» подходит к трею, забирает эту фигуру (съедает/уносит), на её место приходит свежая (новая функция движка `replaceTrayPiece(state, trayIndex)`, см. §20/03).
- **Идеальный UI:** доступно только при наличии действительно непомещаемой фигуры; явная, читаемая анимация «взял → новая появилась»; подтверждение не нужно, но действие отменяемо в окне ~1с (undo-тост); кулдаун-индикатор; ноль случайных срабатываний.

### 9.3. Общее
- Кулдаун — по `helpersUsedDay` (дата последнего использования каждого), сбрасывается в полночь локально (как стрик).
- Если маскот скрыт в настройках — помощники недоступны (они «его»).
- Доступность: цели тача ≥44pt, не зависят от цвета (иконка+форма), уважение reduce-motion.

## 10. Цикл взаимодействия

### 10.1. Тап
- Тап по «Капи» → мгновенная эмоция-реакция (сердечко/подпрыгнул/потянулся), маленький дофамин «он меня заметил». Кулдаун на одинаковую реакцию.

### 10.2. Ежедневное «кормление» (крючок возврата)
- Раз в день над «Капи» появляется иконка-вкусняшка (блок). Тап → «Капи» съедает блок → **`dailyFeedXp`** + довольная анимация.
- Завязано на день (`lastFedDay`, `todayISO` из streak-логики). **Без guilt:** не покормил — «Капи» просто чуть грустнее (sad-настроение), **никаких пушей/гайки**. Иконка не мигает агрессивно.
- Связь со стриком: кормление можно показывать после первой партии дня (рифма со `markPlayedToday`).

### 10.3. Перетаскивание
- Зажал «Капи» → поднимается (как фигура: scale↑, тень), можно подвигать по полу. Отпустил на полу → приземляется с лёгким пуфом, продолжает idle-петлю.

### 10.4. Уронил вниз / выкинул → «потерялся»
- Если отпустить «Капи» **ниже пола** (на доску/за её низ) или за пределы экрана:
  1. «Капи» падает вниз сквозь доску (анимация), исчезает.
  2. Единственная игровая текст-реплика: **«я потеряяялся (((»** (тон по §3.4; варианты в i18n).
  3. Ставится `lost = true` (персист).
- **Возврат:** в начале следующей партии (`newGame`/старт) «Капи» входит заново с пуфом появления; `lost = false`.
- **Без наказания:** XP/уровень/косметика сохраняются — только лёгкая «вина-милота».

### 10.5. Мини-экран «Капи» (гардероб)
- Доступ: тап по чипу уровня (или долгий тап по «Капи»). Неблокирующий лист/оверлей: текущий уровень и XP, превью «Капи», сетка разлоченной косметики со слотами для надевания, заблокированные — затемнены с подписью «ур. N».
- Здесь же — статус помощников (доступен/кулдаун).

### 10.6. Настройки
- Тумблер **«Показывать Капи»** (вкл по умолчанию) в Settings (§20/01). Выкл → слой/мозг не монтируются, помощники недоступны, состояние сохраняется.

## 11. Первый заход — интро

- **Триггер:** старт **первой** партии (а не до игры — анти-чеклист «2 касания без попапов»).
- **Формат:** неблокирующие beat'ы поверх уже идущей партии; **любой тап по экрану сворачивает**; показывается **один раз** (флаг `introDone`).
- **4 кадра:**
  1. «Капи» спрыгивает на пол с пуфом — текст «Привет! Я Капи 🫧» (~1с).
  2. Машет лапкой — «Живу тут, наверху 👋» (~1.5с, дальше можно играть).
  3. **После первой очистки** XP-бар наполняется на глазах — «Ты играешь — я расту 📈» (учим показом, не инструкцией).
  4. Намёк на цель (силуэты эволюции → 👑) — «Заходи каждый день — стану легендой». Дальше «Капи» молчит (только эмоции).
- Тексты — в `core/i18n` (ru/en × 2 тона). Работает оффлайн.

## 12. Архитектура

Новый модуль `features/mascot/` с public API через `index.ts` (правило 02). Чистая логика — без импортов React/RN, покрыта Jest.

```
src/features/mascot/
├── index.ts                  # public API (компоненты-слой, useMascotStore, типы)
├── store.ts                  # zustand + персист MMKV
├── logic/                    # ЧИСТЫЙ TS (тестируемый)
│   ├── config.ts             # MASCOT_CONFIG: XP-ставки, пороги, награды, каталог действий, кулдауны
│   ├── progression.ts        # totalXp → {level, stage, xpInLevel}; rewardForLevel()
│   ├── behavior.ts           # nextAction() — weighted-scheduler на mulberry32
│   └── cosmetics.ts          # каталог косметики (id, slot, minStage, render-параметры)
├── components/
│   ├── MascotLayer.tsx       # позиционирование над доской, gesture (tap/drag), монтаж по настройке
│   ├── Mascot.tsx            # анимированный «Капи» (View-композиция + Reanimated)
│   ├── MascotChip.tsx        # уровень + XP-бар
│   ├── SpeechBubble.tsx      # текст ТОЛЬКО для потери/интро
│   ├── FeedPrompt.tsx        # иконка кормления
│   ├── LevelUpReveal.tsx     # сюрприз-распаковка
│   ├── HelperHint.tsx        # помощник A
│   ├── HelperSwap.tsx        # помощник B
│   ├── Wardrobe.tsx          # мини-экран «Капи» (§10.5)
│   └── MascotIntro.tsx       # интро (§11)
├── hooks/
│   └── useMascotBrain.ts     # тик планировщика; подписка на game-события; пауза на drag
└── __tests__/
    ├── progression.test.ts
    └── behavior.test.ts
```

### 12.1. Зависимости (только в разрешённом направлении, 02)
- `features/mascot → core/engine` (findPlacements/hasPlacement/rng), `core/i18n`, `core/storage`, `features/settings` (тон, showMascot, sound/vibro), `ui` (токены).
- `features/game` остаётся независимым; интеграция — через подписку маскота на `useGameStore` и через **колбэки**, переданные в игровой экран (маскот не импортируется внутрь game-модуля).
- Экран `app/game.tsx` композирует `<MascotLayer/>` поверх зоны над доской.

### 12.2. Интеграция с drag (перф)
- Маскот читает shared value `dragActive` (выставляется drag-системой на захвате/дропе) и **замирает на время drag** на UI-потоке; JS-тик мозга на это время не запускается. Ноль ререндеров во время drag сохраняется (07).

### 12.3. Точки, требующие правок движка/стора (минимум)
- `core/engine`: добавить `replaceTrayPiece(state, trayIndex, config)` (взвешенный пик одной фигуры, переиспользуя `pickWeighted`/`makeWave`) — для помощника B. С тестом.
- `features/game/store`: экшен `replaceTrayPiece(trayIndex)` (обёртка над движком + автосейв) и экспорт shared `dragActive` (или флага старта/конца drag).

## 13. Состояние и персист (MMKV)

Новый ключ `mascot.state` (JSON), регистрируется в `core/storage/KEYS`:
```ts
interface MascotState {
  totalXp: number;
  level: number;            // 1..24 (кэш)
  unlocked: string[];       // id косметики
  equipped: Partial<Record<Slot, string>>;
  lastFedDay: string | null;          // YYYY-MM-DD
  helpersUsedDay: { hint?: string; swap?: string };  // YYYY-MM-DD
  lost: boolean;
  introDone: boolean;
  rngState: number;         // seed планировщика поведения
}
```
- Запись — на изменения (левел-ап, кормление, надевание, потеря/возврат, использование помощника). Поведенческий rngState можно не персистить каждую смену действия (дёшево, но не критично) — пишем периодически/на значимых событиях.
- `mood` и текущее `action` — **в памяти**, не персистятся.

## 14. i18n (только тексты потери и интро)

`core/i18n` (ru/en), две тональности (Классика/Дерзкий), значения — массивы вариантов (рандом):
```
mascot.lost.*        // «я потеряяялся (((» / дерзкий вариант; EN аналогично
mascot.intro.1..4    // 4 beat'а интро × тон
```
Пример:
| Ключ | Классика (ru) | Дерзкий (ru) |
|---|---|---|
| mascot.lost | я потеряяялся ((( | ну и куда ты меня… теперь ищи |
| mascot.intro.3 | Ты играешь — я расту | фарми, я левелюсь с тебя |

EN — аналогично. Никаких других реплик у «Капи» нет.

## 15. Настройки и доступность
- Settings: тумблер «Показывать Капи» (дефолт вкл) → ключ в `settings.v1` (`showMascot`).
- reduce-motion (OS, через `AccessibilityInfo`): спокойная анимация, без резких действий, без частых эмотов.
- Цели тача ≥44pt; помощники/тап не зависят от цвета (форма+иконка).

## 16. Звук и хаптика (тонко, по настройкам)
- Новые короткие сэмплы (через `scripts/gen-sounds.js`, ≤50КБ): `feed` (мягкий «ам»), `levelup` (короткая фанфара), `lost` (нисходящий блип). Тап — selection-хаптика; кормление — impact light; левел-ап — notification success.
- Всё гейтится `sound`/`vibro` из настроек; во время drag не звучит (не мешать core-фидбеку).

## 17. Производительность (бюджет, спека 07)
- Только transform/opacity; freeze на drag; ноль ререндеров в drag-пути; JS-тик мозга ≤ раз в ~2с и **отключён во время drag**.
- **Ноль новых нативных зависимостей** (Views + `expo-linear-gradient` + Reanimated; опц. лёгкие PNG через `expo-image`).
- Пулы частиц/конфетти для распаковки — переиспользуем существующие (`effects/`), без mount/unmount в горячем пути.
- reduce-motion и тумблер «Показывать Капи» как разгрузка на слабых устройствах.
- Проверка: release-сборка, Perf monitor; маскот не должен добавлять дропов кадров во время drag/очистки.

## 18. Монетизация (будущее, без P2W)
- v1: всё бесплатно (косметика — за уровни, помощники — за уровни + раз в день).
- v1.1 (заложено, не реализуем): платные косметические паки/сезонные скины «Капи» как IAP-косметика (паттерн 05). **Помощники никогда не продаются** — только зарабатываются игрой. Анти-P2W сохраняется.

## 21. Граничные случаи
- **Потерян через рестарт приложения:** `lost` персистится; возврат — на следующем старте партии.
- **Полночь/таймзона:** кормление и кулдауны через `todayISO` (как стрик), без сетевого времени.
- **Маскот выключен в настройках:** слой/мозг/помощники не активны; состояние и прогресс сохраняются; при включении — продолжает с того же уровня.
- **Continue vs New game:** прогресс маскота не зависит от партии (живёт между партиями).
- **Revive:** «Капи» реагирует (оживился), не сбрасывается.
- **Несколько левел-апов за ход:** дайджест-распаковка «+N предметов», без очереди оверлеев.
- **MAX-уровень:** XP-бар замирает на «легенде», кормление даёт только эмоции.

## 22. Вне scope (v1.1+)
- Платные косметические паки/сезонные скины, «престиж» после MAX, ночной режим поведения как отдельная фича, мини-игры с «Капи», шеринг-карточка с маскотом, синхронизация прогресса в облако.
