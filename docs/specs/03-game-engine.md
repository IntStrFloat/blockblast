# 03 — Игровой движок (core/engine)

Статус: утверждено · Обновлено: 2026-06-12
Чистый TypeScript, ноль импортов React/RN. Все числа — из `GameConfig` (дефолты ниже), логика не хардкодит ничего.

## Правила (как в оригинальном Block Blast)

- Доска **8×8**. Фигуры **нельзя вращать**.
- Выдаётся **волна из 3 фигур**. Следующая волна — только когда размещены все 3.
- Размещение валидно, если все клетки фигуры попадают в пустые клетки доски.
- После размещения одновременно проверяются **все 8 строк и 8 столбцов**: полностью заполненные очищаются разом (пересечения считаются один раз).
- **Game over**: ни одна из оставшихся в трее фигур никуда не влезает. Проверка после каждого размещения и после выдачи волны.
- Гравитации нет — блоки остаются на местах.

## Данные

```ts
type Cell = number;            // 0 = пусто, 1..N = colorId
type Board = Cell[];           // длина 64, индекс r*8+c
interface Shape { id: string; cells: [r, c][]; w: number; h: number; weight: number }
interface PieceInstance { shape: Shape; colorId: number }
interface GameState {
  board: Board;
  tray: (PieceInstance | null)[];   // длина 3
  score: number;
  combo: number;                    // текущая серия очисток
  movesSinceClear: number;
  status: 'playing' | 'over';
  reviveUsed: boolean;
  rngState: number;                 // mulberry32, детерминизм
}
```

## Каталог фигур

Повороты = отдельные фигуры в пуле (вращения нет). Набор (≈40 форм):

| Группа | Формы | Вес (за форму) |
|---|---|---|
| Линии гориз./верт. | 1×2, 1×3, 1×4, 1×5 (+вертикали) | 1.0; 1×5 — 0.6 |
| Точка | 1×1 | 0.5 |
| Квадраты | 2×2, 3×3 | 1.0 / 0.7 |
| Прямоугольники | 2×3, 3×2 | 0.9 |
| Уголки 3 кл. | L-мини, 4 ориентации | 1.0 |
| L 4-5 кл. | J/L по 4 ориентации | 0.8 |
| T 4 кл. | 4 ориентации | 0.8 |
| S/Z 4 кл. | по 2 ориентации | 0.7 |
| Диагонали нет — все фигуры связные ортогонально | | |

Генерация волны — см. **[Dynamic spawn director](#dynamic-spawn-director)**: 3 фигуры за волну (повторы разрешены, как в оригинале), вес и целевая масса зависят от заполненности поля, цвет — равномерно из палитры (6 цветов). Политика `trayPolicy`:
- `'pure'` (дефолт): динамический спавн с гарантией, что вся тройка раскладывается в каком-то порядке;
- `'pity'`: усиленный спасательный биас (мелкие/влезающие фигуры) для лёгкого режима.

## Скоринг (GameConfig.scoring, дефолты = формула оригинала, см. 00)

- Размещение: `+cells` (число клеток фигуры).
- Очистка одним ходом: `base = clearedCells · 10 + lineBonus[L]`, где `lineBonus = {1:10, 2:20, 3:60, 4:120, 5:200, 6+:300}`. Пример: 1 строка = 8·10 + 10 = 90.
- **Полная очистка доски** после хода: `+360` (boardClearBonus).
- Комбо: `combo` растёт на 1 за каждое размещение с очисткой подряд; размещение без очистки сбрасывает в 0 (`comboForgiveness: 0` ходов — конфигурируемо).
- Множитель комбо: `total = floor(base · (1 + 0.5 · max(combo - 1, 0)))`. combo=1 → ×1, combo=3 → ×2.
- **Тир похвалы** за ход: 1 линия → `good`, 2 → `great`, 3 → `amazing`, ≥4 → `unbelievable`; при combo ≥ 3 — флаг `onFire`.

Все значения — в `GameConfig.scoring`, балансируются без правки логики.

## API движка (всё — чистые функции)

```ts
createGame(seed?: number): GameState
canPlace(board, shape, r, c): boolean
findPlacements(board, shape): Array<[r, c]>        // подсветка/«фигура никуда не влезает»; основа подсказки и «стак»-эвристики маскота (09)
hasPlacement(board, shape): boolean                // помещается ли фигура; основа помощника «замена» (09)
hasAnyMove(board, tray): boolean
place(state, trayIndex, r, c): { state: GameState; event: PlacementEvent }  // throws при невалидном
replaceTrayPiece(state, trayIndex): GameState       // свежая фигура в слот (помощник «замена» маскота, 09); exclude по другим слотам
revive(state): GameState                            // очистка доски, reviveUsed=true, счёт/комбо сохраняются
serialize(state): string / deserialize(s): GameState // версионированный формат для автосейва

interface PlacementEvent {
  placed: [r, c][]; colorId: number;
  clearedRows: number[]; clearedCols: number[]; clearedCells: [r, c][];
  scoreDelta: number; score: number;
  combo: number; praise: 'none'|'good'|'great'|'amazing'|'unbelievable'; onFire: boolean;
  newTray: boolean;        // эта установка добрала волну → трей перевыдан
  gameOver: boolean;
}
```

UI не лезет в доску напрямую — только проигрывает `PlacementEvent`.

## RNG

`mulberry32(seed)` — 10 строк, детерминированный. `rngState` хранится в `GameState` → автосейв полностью воспроизводим, тесты не флейкают.

## Dynamic spawn director

Выдача каждой новой тройки **адаптивна по заполненности поля** (в духе оригинала, см. [00](00-game-analysis.md#генерация-фигур-адаптивность-оригинала)). Цель — динамика: **пусто → крупные** фигуры (быстрый набор очков и быстрый клир), **забито → мелкие/диагонали/одиночки** (влезают в щели, игрок не застревает). Это **заменяет** прежний «opening director» (первые волны жёстко крупными): на пустом поле адаптивная кривая и так выдаёт крупные.

**Сигнал заполненности.** `f = filledCells / 64` ∈ [0,1] — доля занятых клеток в момент выдачи тройки (когда трей опустел).

**Целевая масса.** Главный рычаг — целевая суммарная масса тройки (сумма клеток), линейно по `f`:

```
target(f) = lerp(emptyTargetMass, fullTargetMass, f)        // rescue → fullTargetMass
```

- `f = 0` (пусто): `target ≈ emptyTargetMass` (высокая, ~24) → почти всегда 2–3 крупных блока (`sq3`/`rect`/`sq2`).
- `f = 1` (забито) или rescue: `target ≈ fullTargetMass` (низкая, ~6) → мелкие/диагонали/одиночки в щели.

Это даёт **надёжный пол** массы (не «как повезёт»): на пустом поле старт стабильно крупный, по мере заполнения мельчает.

**Кандидаты и выбор.** Чтобы попасть в `target`, сэмплим `candidates` трэев и берём тот, чья масса **ближе всего к target** (в пределах `SPAWN_MASS_MARGIN` от лучшего — случайно, ради вариативности). Кандидаты сэмплятся size-biased весом, экспонента которого меняет знак по `f` (так пул содержит крупные при пусто и мелкие при забито):

```
w(shape, f) = shape.weight · cells ^ (sizeBias · (1 − 2·f))
```

**Повторы разрешены** (как в оригинале): формы в тройке могут совпадать — отсюда «несколько 3×3 за ход» на пустом поле. Цвет — равномерно из палитры.

**Алгоритм:**
1. Считаем `f`, `rescue` (см. ниже), `target` и вес `w(·, f)`.
2. Сэмплим `candidates` трэев (с повторами), оставляем только полностью раскладываемые (`canPlayEntireTray`).
3. Берём кандидата с массой, ближайшей к `target` (рандом среди near-ties).
4. Если ни один не раскладывается (очень тесная доска) → `findPlayableShapeSequence` (с повторами) гарантирует решаемый трей.

**Спасательный биас (rescue).** Триггер: `f ≥ rescueFullness` (напр. 0.8) **или** `rescueDryStreak` ходов подряд без очистки. Эффект: `target = fullTargetMass` и size-bias клампится к мелкому концу — мелкие/влезающие фигуры приходят заранее, а не только через фолбэк.

**Честность (осознанное отличие от оригинала — см. 00):** вся тройка всегда раскладывается. `trayPolicy: 'pure'` теперь означает «динамический спавн с гарантией решаемости» (а не «честный рандом с возможными тупиками»); `'pity'` — усиленный rescue для лёгкого режима.

**Тюнинг — в `GameConfig.spawn`** (числа не в логике): `{ candidates, sizeBias, emptyTargetMass, fullTargetMass, rescueFullness, rescueDryStreak }`. Базовые `shape.weight` остаются пер-фигурными тюнерами.

**Детерминизм и совместимость.** Генерация детерминирована от `rngState` + доски (доска воспроизводима из истории ходов). `waveNumber` больше **не** управляет режимом спавна (директор зависит только от поля) — пункт миграции save «v1 стартует на волне 3, чтобы не входить в opening-режим» теряет смысл; счётчик можно оставить как статистику/прогрессию. **Любое изменение спавна двигает engine fingerprint → нужен rebuild + redeploy бэкенда** (триггер в `fingerprint.test.ts`).

## Тесты (Jest, обязательное покрытие)

1. Каталог: все формы связные, в границах bbox, веса > 0, id уникальны.
2. `canPlace`: границы, пересечения, пустая/полная доска.
3. Очистки: строка, столбец, строка+столбец одним ходом (пересечение один раз), 4 линии разом.
4. Скоринг: таблица кейсов по формуле, комбо-серии (рост, прощение одного хода, сброс после двух).
5. Game over: тупик после размещения и сразу после выдачи волны; `revive` возвращает в игру.
6. Сериализация: roundtrip, отбрасывание битых/чужих версий.
7. Детерминизм: одна seed → идентичная последовательность волн.
