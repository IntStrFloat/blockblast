# 02 — Архитектура

Статус: утверждено · Обновлено: 2026-06-12

## Принципы

1. **Движок отделён от UI.** Вся игровая логика — чистый TypeScript без единого импорта из React/React Native. Тестируется обычным Jest за миллисекунды, переносима (web, сервер, боты).
2. **Модули = папки features/** с одной зоной ответственности. Модуль наружу отдаёт только то, что экспортирует его `index.ts` (public API). Кросс-импорты внутрь чужого модуля запрещены.
3. **Интеграции за интерфейсами.** Реклама, IAP, аналитика — это интерфейсы с Noop-реализацией по умолчанию. Реальные SDK подключаются адаптерами и включаются флагами. Приложение всегда собирается и работает без них.
4. **Состояние**: zustand-сторы по модулям. Персист — MMKV (синхронный, быстрый). Никакого глобального «god store».
5. **Конфиг вместо хардкода**: все игровые числа (очки, веса фигур, частота рекламы) — в конфиг-объектах, меняются без правки логики.

## Зависимости между модулями (только в этом направлении)

```
app → features → core, ui
features/game → core/engine (использует), features/monetization (revive), features/settings (звук/вибро)
core/* → ничего из features/ui/app
ui → ничего, кроме токенов и RN
```

## Поток данных игры

```
жест (gesture-handler, UI-поток)
  → worklet считает клетку под пальцем → shared values (превью)
  → onDrop (JS): engine.place(state, ...) → новый стейт + события
  → useGameStore.set(...) → React рендерит доску
  → события (cleared, combo, praise) → эффекты: анимации/звук/хаптика
  → автосейв партии в MMKV (throttle)
```

Движок возвращает **события размещения** (какие клетки легли, какие линии очищены, дельта счёта, комбо, тир похвалы) — UI-слой только проигрывает их. Это единственный контракт между логикой и графикой.

## Технологический стек

| Слой | Выбор | Почему |
|---|---|---|
| Платформа | Expo SDK 56, RN 0.85, New Architecture, Hermes | проверенный локальный release-пайплайн под RuStore |
| Навигация | expo-router | стандарт Expo, typed routes |
| Анимации | react-native-reanimated 4 + worklets | 60fps на UI-потоке |
| Жесты | react-native-gesture-handler 2 | drag без JS-моста |
| Состояние | zustand | минимум кода, селекторы против лишних рендеров |
| Персист | react-native-mmkv | синхронный, в разы быстрее AsyncStorage |
| Звук | expo-audio | актуальная замена expo-av |
| Хаптика | expo-haptics | стандарт |
| Рендер доски | обычные View + Reanimated | 64 ячейки + 3 фигуры — Skia не нужен, меньше нативных зависимостей (см. 07) |

## Расширяемость (заложено, не реализовано)

- Новые режимы: движок принимает `GameConfig` (размер доски, набор фигур, скоринг) — Adventure-режим = другой конфиг + свой стор.
- Скины: палитры блоков — массив тем в `ui/theme.ts`, экран настроек уже умеет выбирать.
- Лидерборд: Node.js API принимает только одноразовые билеты и переигрывает seed/ходы
  через тот же детерминированный engine. Клиентский score не считается доверенным.
- Offline-first: очередь результатов ограничена 20 партиями и отправляется после восстановления сети.
- Аналитика: локальная минимальная очередь с opt-out; серверная отправка в v1.1 отключена.

## Тестирование

- `core/engine` — Jest, полное покрытие правил (формы, размещение, очистки, скоринг, game over, RNG-детерминизм).
- Сторы — unit-тесты ключевых переходов (стрик через полночь, реконсиляция entitlements).
- UI — без снапшот-простыней; смоук через ручную проверку + типизация.
- Команды: `npm test`, `npx tsc --noEmit` — обе зелёные перед каждым коммитом.
