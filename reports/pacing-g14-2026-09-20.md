# G14 — темп без искусственных пауз

## Решение

- `useDelayedTray` больше не скрывает committed refill: новая тройка доступна в
  том же безопасном store commit, включая last-piece clear. Pooled clear layers
  продолжают прошлый эффект независимо и сохраняют same-commit bridge.
- Adventure использует один outcome lifecycle из `EFFECT_SEQUENCE_TIMING`:
  normal score win 520 ms, reduced motion 120 ms, jewel arrival + 120 ms и
  bounded fallback 920 ms, если presentation layer недоступен.
- Во время `settling` появляется явное «Показать результат». Оно ускоряет только
  переход к сохранённому result и никогда не запускает следующий уровень.
- Fail path сохраняет afterglow только для реального clear; reduced motion не
  ждёт декоративную сцену.

## Приёмка

- single/multi-clear и last-piece refill получают interactive tray без 300-ms
  empty state;
- rapid placement/clear presentations остаются bounded отдельными pools;
- background/unmount чистят presentation timers, durable board/tray уже сохранены;
- финальный Adventure move сохраняет terminal snapshot до lifecycle и result;
- reduced-motion и explicit skip не влияют на reward/next-level actions.

## Метрики

`turn_input_ready` измеряет commit→tray-ready по mode/newTray/clear. Для refill
событие испускается только после `measureInWindow` всех новых TrayPiece и помечено
`readiness_source=native_layout`; для оставшегося уже смонтированного tray —
`existing_tray`. Это не подменяется `setTimeout(0)`.
`adventure_result_ready` — win→result и explicit acceleration,
`effect_conflict` — одновременно активные clear/placement presentations.
`scripts/analytics/pacing-g14.sql` даёт p50/p95/p99 tray-ready latency, p95
win→result и конфликтующие effects. Изменение темпа не смешивается с difficulty.

Здесь p95 относится к product-level tray readiness. Физическую touch→frame input
latency нельзя честно получить JS-событием; она измеряется нативным frame/input
trace в G15 и не заявляется по `turn_input_ready`.
