# G08 — справедливые недельные награды

## Источник права

Право на приз определяется только неизменяемым серверным архивом закрытой недели.
Cached client snapshot и `previousSnapshot.rank` не участвуют в eligibility.

Сервер лениво архивирует все ещё не сохранённые закрытые недели, представленные в
`runs`. Порядок полностью детерминирован:

1. лучший score по убыванию;
2. число завершений по возрастанию;
3. время первого достижения лучшего score по возрастанию;
4. стабильный server userId лексикографически.

Каждое право имеет `rewardId = player + week + reward bundle`. Claim сохраняет
receipt до ответа и на любой повтор возвращает тот же receipt. API возвращает и
непризовые финальные результаты, поэтому клиент различает «итог #10» и «итог ещё
не подтверждён».

## Клиент и G03

- Подтверждённые outcomes и receipts сохраняются локально до применения эффекта.
- XP применяется через `progression.grantReward` с server rewardId как
  `completionId`; повторный claim/remount/process death дают нулевую дельту.
- Косметика повторно сверяется из каждого сохранённого server receipt, поэтому
  сбой между XP и гардеробом восстанавливается.
- Старая `claimed:true` локальная награда сохраняется и не начисляется заново.
  Старая `claimed:false` запись cached-rank не считается правом до подтверждения
  сервера.

## Несколько устройств

Claim глобально идемпотентен для серверного профиля. Общая прогрессия остаётся
локальной MMKV-моделью без cloud save; `effectScope=local_profile` заявляет это
явно. Каждый локальный профиль зеркалирует один server receipt через свой G03
ровно один раз. Синхронизация баланса между устройствами не обещается.

Backend рассчитан на один Node writer: синхронная read/mutate/atomic-rename секция
сериализует конкурентные claim внутри одного процесса. Для нескольких процессов
потребуется БД или межпроцессный lock.

## UI и метрики

До серверного итога показываются отдельные состояния «подводим итог» и «нет сети»;
cached content не стирается. После подтверждения показывается финальное место,
eligible reward, claim pending/error/retry или подтверждённое отсутствие приза.
Несколько пропущенных наград доступны последовательно.

`scripts/analytics/weekly-prize-metrics.sql` считает eligible→claim→applied,
ошибки по stage/code и claim→следующую партию.
